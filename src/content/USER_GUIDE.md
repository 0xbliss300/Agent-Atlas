## 快速开始

首次打开应用时不会出现演示项目。你可以从页头选择“添加项目”，手工填写项目，也可以让浏览器读取你明确选择的项目目录或状态文件并生成可编辑草稿。

最短使用流程：

1. 选择“添加项目”。
2. 选择空白项目或一个内置模板。
3. 填写项目名称、一句话简介、状态、完成度和当前里程碑。
4. 检查可选的任务、阻塞项、技术信息和本地资源。
5. 创建项目并在详情页继续维护。
6. 定期从“设置”导出 JSON 备份。

页面使用 Hash 路由。你可以刷新页面或使用浏览器的前进、后退按钮，不需要为各个页面配置服务器重写规则。

| 主要页面   | 入口          | 用途                               |
| ---------- | ------------- | ---------------------------------- |
| 项目概览   | `#/`          | 浏览、搜索、筛选和置顶项目         |
| 开发工作台 | `#/workbench` | 汇总跨项目任务、阻塞项和停滞提示   |
| 研究笔记   | `#/notes`     | 创建和阅读项目关联的 Markdown 文档 |
| 使用指南   | `#/guide`     | 阅读当前这份本地指南               |

## 添加与编辑项目

项目名称、一句话简介、当前状态、完成度和当前里程碑是必填信息。状态可选择“规划中”“开发中”“已暂停”或“已完成”，完成度范围为 0～100。

高级信息中可以维护：

- 完整介绍与图标类型；
- 功能列表和三阶段路线图；
- 下一步任务与当前阻塞问题；
- 语言、框架、模型、数据源和本地启动命令；
- 本地目录、GitHub 地址、文档位置、演示地址和本地产物路径；
- 一行一条的人工开发记录；
- 最多 12 个标签、置顶状态以及多个项目集合。

功能列表每行使用 `功能名称 | 状态`，路线图每行使用 `阶段 | 说明 | done/current/next`。任务和阻塞项可以使用普通文本，也可以使用 `- [ ]`、`- [x]` Markdown 勾选格式。

```text
对话工作流 | 已完成
浏览器验收 | 开发中

基础能力 | 完成数据层 | done
当前迭代 | 接入前端页面 | current
后续增强 | 补充更多功能 | next
```

创建或编辑前可以套用模板。模板只会填充表单，必须由你检查并确认后才会保存项目。关闭包含未保存内容的表单时，页面会要求确认。

项目详情页提供编辑、复制和删除。复制会生成新的项目 ID；删除项目需要二次确认，项目会与其研究笔记、草稿、版本历史和自动事件一起移入回收站，7 天内可在“设置 → 回收站”中一键恢复。

## 项目概览与组织

概览页会根据当前项目计算项目总数、开发中数量、平均完成度和最近更新。搜索框为全局搜索：除匹配项目名称、简介、当前里程碑、标签和技术关键词外，还会检索研究笔记标题与 Markdown 正文、未完成任务和未解决阻塞项。命中结果按"研究笔记"与"任务与阻塞"分组展示，点击可直达对应笔记或项目详情页；搜索为即时派生，不落库，笔记删除后立即从结果消失。

你可以组合使用状态、标签和集合筛选，并按最近更新、完成度或项目状态排序。选择"清除筛选"可以回到完整范围，结果数量会通过无障碍状态区域播报，搜索时还会补充命中的笔记与任务计数。

标签会自动去除首尾空格、空值和不区分大小写的重复项。每个项目最多 12 个标签，每个标签最多 24 个字符。卡片最多显示前三个标签，多出的标签以数量提示收起。

项目可在表单或概览卡片中置顶。置顶只会让项目在“最近更新”排序中提前，不会修改项目更新时间；完成度和状态排序不受置顶影响。

在"设置 → 项目集合"中可以创建、重命名、调整顺序和删除集合，一个项目可同时属于多个集合。删除集合只会解除关联，不会删除项目、研究笔记、任务、草稿、版本历史或时间线。

### 最近访问栏

概览页 hero 下方会按访问时间倒序显示"最近访问"栏，每条记录展示项目状态点、名称和相对时间（如"3 分钟前""2 小时前""3 天前"，超过一周显示日期）。点击任意条目直接跳转到该项目详情页。

每次从其他路由进入 `/project/:id` 或 `/project/:id/notes` 时，对应项目会被记录为最近访问并移到最前；重复访问同一项目会更新时间戳而不会新增条目。列表上限为 8 条，超出会按访问时间裁剪最旧条目。如果被访问的项目被删除，对应条目自动从栏中消失。

"清空"按钮可一次性清除全部最近访问记录。最近访问作为独立的本地状态保存在 `data/recent-access/recent-access.json`，与显示设置一样不会进入完整 JSON 备份；其他浏览器或设备的访问历史互不共享。

## 键盘快捷键与命令面板

高频用户可以不离开键盘完成跳转、新建和搜索。快捷键默认开启，可在"设置 → 显示偏好"中关闭；关闭后命令面板仍可通过页头"命令"按钮打开。

| 快捷键               | 作用               |
| -------------------- | ------------------ |
| `Ctrl` / `Cmd` + `K` | 打开命令面板       |
| `/`                  | 聚焦概览页搜索框   |
| `n`                  | 新建项目           |
| `g` 然后 `w`         | 跳转到开发工作台   |
| `g` 然后 `n`         | 跳转到研究笔记     |
| `?`                  | 查看快捷键列表     |
| `Esc`                | 关闭命令面板或弹窗 |

单键快捷键（`/`、`n`、`g`、`?`）在输入框、文本域等可编辑控件中自动屏蔽，避免影响输入；`Ctrl/Cmd+K` 在任何位置都可用。命令面板支持模糊搜索项目、研究笔记与页面跳转，方向键选择、回车执行，结果数量通过无障碍状态区域播报。

## 操作反馈

保存项目、删除项目、导入备份、清空数据等关键操作会在页面右下角显示可见 Toast。成功类 Toast 约 3 秒后自动淡出；错误类 Toast 会一直显示，直到点击关闭按钮或按 `Esc` 关闭。同一位置的 Toast 会被后续操作替换，避免堆叠。

Toast 与页头旁的无障碍 `aria-live` 区域并行工作：视力用户看到 Toast 的同时，辅助技术也会通过状态区域听到相同内容。Toast 尊重系统的 `prefers-reduced-motion` 设置，关闭减弱动态效果时会禁用进入和退出动画。

## 危险操作确认

删除项目、删除研究笔记、清空回收站、清空全部本地内容、删除集合、删除自定义模板，以及关闭包含未保存内容的表单或笔记时，应用会弹出居中卡片式的确认对话框，明确显示将要操作的对象名称与影响范围，不再调用浏览器的原生 `window.confirm`。

危险操作（如删除、清空）的确认按钮使用警示色，初始焦点落在“取消”以防误触；非危险操作（如关闭未保存表单）的初始焦点落在“确认”以提升效率。可以用 `Esc` 取消、`Tab`/`Shift+Tab` 在两个按钮间循环、点击遮罩区域取消；对话框打开期间，下方面板的 `Esc` 处理会被抑制，避免误关底层模态。同时打开可见 Toast 时，Toast 的 `Esc` 关闭会暂时失效，让位给确认对话框。

## 首次使用引导

首次进入没有项目的概览页时，会自动弹出三步引导：介绍本地优先工作区、引导添加或导入第一个项目，并说明开发工作台与研究笔记的用途。引导可随时跳过，跳过后不再自动出现；一旦创建或导入了第一个项目，引导也会自动标记为完成。

首次进入工作台或研究笔记页时，若引导仍未完成，页面顶部会显示轻量提示，说明该页用途并提供“开始引导”与“跳过”入口。在“设置 → 显示偏好”中可以重新启动引导，重启后会回到概览页再次弹出向导。引导状态保存在本地显示偏好中，不进入完整 JSON 备份。

## 项目详情、任务与阻塞项

项目详情集中展示当前状态、完成度、里程碑、功能、路线图、项目链接、技术栈、运行信息、研究笔记、开发记录和自动变更时间线。

“下一步任务”可以直接勾选或重新打开，修改会立即写回项目。“当前阻塞问题”只显示未解决内容，可在开发工作台中标记解决。两类操作都会形成自动变更事件。

本地目录、文档路径和产物路径只是文本。对应按钮会复制文本，不会打开文件管理器。HTTP 或 HTTPS 资源可在新窗口打开；本地演示地址只有在相应服务已经运行时才有效。

## 开发工作台

[开发工作台](#/workbench)从现有项目和研究笔记实时派生执行视图，不保存额外的汇总副本。

默认执行顺序为：

1. 未解决阻塞；
2. 活跃项目的未完成任务；
3. 其他未完成任务；
4. 可能停滞的项目。

“可能停滞”不是项目事实，只表示项目尚未完成，且最后更新时间距今至少 14 天。工作台支持按项目、集合和内容类型筛选，也可以直接勾选任务、解决阻塞项或返回准确来源继续开发。

页面底部的“近期来源”提供最近项目和研究笔记入口。项目或集合筛选会同时限制执行队列和相关汇总。

## 研究笔记与版本恢复

[研究笔记](#/notes)是归属于具体项目的 Markdown 文档，与项目表单中的简短“开发记录”分开保存。

新建或编辑笔记时可以填写所属项目、标题和 Markdown 正文。桌面端并排显示编辑器与实时预览；移动端可在“编辑”和“预览”之间切换。预览支持标题、列表、任务列表、引用、链接、代码和表格。

编辑器会把未保存内容作为临时草稿分类保存在项目的 `data/drafts/` 中。再次进入时可以恢复或丢弃草稿。每篇正式笔记保留最近 10 个版本，版本保存在 `data/history/`；可查看字段变化和逐行正文差异，并选择旧版本恢复，恢复前当前正式内容也会进入历史，避免覆盖丢失。

草稿和正式版本历史均有明确边界：临时草稿不会进入 JSON 备份，正式版本历史会进入完整备份。

## 项目与笔记模板

添加项目时可使用“空白项目”“Agent 项目”“研究项目”和“自动化项目”。新建研究笔记时可使用“实验记录”“技术调研”“决策记录”和“复盘”等 Markdown 大纲。

项目表单和笔记编辑器都可以把当前结构保存为自定义模板，并支持重命名、复制、排序和删除。删除模板不会影响已经由它创建的项目或笔记。

项目模板默认排除项目 ID、名称、状态进度、更新时间、开发记录、本地路径、资源地址、Git 信息、研究笔记、历史和系统事件。状态、里程碑、开发记录、路径或资源只有在保存模板时逐项明确勾选才会纳入。笔记模板只保存标题和 Markdown 大纲。

## 自动变更时间线

项目关键变化会形成独立时间线，包括项目创建，状态、完成度和里程碑修改，任务勾选，阻塞项解决，本地状态应用，以及研究笔记创建、更新和删除。

一次保存中的多个核心字段变化会合并为一条事件；没有实际变化时不会制造事件。时间线可按项目、状态、任务、阻塞、本地读取和研究笔记类型筛选，并与人工开发记录明确分开展示。

研究笔记事件只保存笔记 ID、标题和动作，不复制完整正文。笔记删除后既有事件仍会保留并标记来源已删除。每个项目只保留最近 200 条自动事件，项目删除时会级联清理对应事件。

## Codex 项目上下文

项目详情页的“生成 Codex 上下文”会在浏览器本地即时生成结构稳定的 Markdown，帮助新的 Codex 会话接手项目。

上下文可包含项目目标、状态、完成度、里程碑、未解决阻塞项、未完成任务、技术栈、运行命令、路径和资源文本、最近开发记录、研究笔记索引，以及由你明确选择的笔记正文。

生成后先在面板中预览，再由你选择“复制 Markdown”或下载 `.md` 文件。内容不会自动发送给 Codex 或任何外部服务。项目路径、仓库地址和研究内容可能包含私人信息，请在复制或下载前检查。

## 从本地来源创建或更新

所有本地读取都必须由你主动选择文件或目录。网页不会扫描未授权路径，也不会根据表单中保存的路径文本自动访问文件系统。

添加项目时可以从以下来源生成草稿：

- JSON 状态文件；
- Markdown 文件；
- `package.json`；
- 你明确选择的项目目录。

目录模式只读白名单内的 README、TODO、状态 JSON、`package.json` 和 Git 分支/提交元数据。文件模式单文件上限为 1 MB，本次总读取量上限为 4 MB。读取结果会标记为“已检测”“需确认”或“未检测到”，你必须在普通表单中检查后再创建。

项目详情的“读取本地状态”使用同一授权边界。结果会先预览，只有选择“应用读取结果”后才会更新项目。应用操作会记录自动事件。

应用不会保存目录句柄、权限或文件内容，也不会虚构浏览器未提供的绝对路径。不支持目录选择的浏览器仍可选择单个状态文件。

## 备份、恢复与清空

在“设置 → 备份与恢复”中可以下载完整 JSON 备份。备份包含项目、Markdown 研究笔记、正式版本历史、自动变更时间线、自定义模板、项目集合和回收站条目；临时笔记草稿不进入备份。

在项目详情页点击“导出”，可以单独导出当前项目及其关联内容。单项目导出文件同样为 JSON 格式，包含该项目、其 Markdown 研究笔记、正式版本历史、自动变更时间线以及所关联的项目集合；不包含自定义模板和临时笔记草稿。导出前会明确提示包含的内容范围。

导入方式有两种：

- **合并导入**：保留当前数据并加入备份；ID 冲突时生成新 ID，同时修正笔记、历史、时间线和集合关联。
- **替换导入**：使用备份中的数据替换当前项目、笔记、历史、时间线、模板和集合。

模板或集合名称冲突时会保留双方并生成清楚的副本名称。旧版仅包含项目的备份也可以导入，缺少的新数据会安全迁移为空。导入校验失败时不会覆盖现有数据。

“设置 → 回收站”可查看已删除的项目和研究笔记，支持单条恢复或彻底删除，也支持一键清空。清空回收站会永久移除其中的条目，需要二次确认。

“清空全部本地内容”会清空 `data/` 分类文件中的项目、研究笔记、草稿、历史、时间线、自定义模板、集合和回收站，且需要二次确认。执行前应先导出备份。

## 显示设置

“设置 → 显示偏好”可以控制：

- 是否显示已完成项目；
- 是否显示“最近更新”区域；
- 默认排序方式；
- 标准或紧凑显示密度。

显示偏好保存在 `data/settings/settings.json`，但不属于完整 JSON 备份。设置面板还会展示当前项目、研究笔记、自动事件、自定义模板和集合数量，以及“网络发布已关闭”的本地状态。

## 本地数据与安全边界

项目坚持 local-first：

- 项目、笔记、草稿、历史、事件、模板、集合和显示偏好分类写入项目根目录的 `data/`；
- 本地文件接口只监听 `127.0.0.1`，只接受预定义数据分类，不接受任意路径；
- 不提供远程后端、账号、遥测、云同步或远程 Markdown 服务；
- Markdown 原始 HTML、脚本、事件属性和危险 URL 不会执行，远程图片不会加载；
- 外部 HTTP/HTTPS 链接在新窗口打开，并使用安全的窗口隔离属性；
- 文件和目录读取只发生在你明确授权之后；
- 本地路径只作为文本保存和复制；
- 应用不会自动发布，也不应被部署到公开网络。

写入采用临时文件和原子替换，页面底部会显示“正在保存”“已保存”或保存失败状态。损坏文件会保留原件并按分类报告，不会静默覆盖。首次升级时，缺失的分类会从旧版浏览器 `localStorage` 迁移；已有文件始终优先，迁移失败不会删除旧浏览器数据。

真实 `data/` 内容默认被 Git 忽略。项目路径、日志、仓库地址和研究内容仍可能包含私人信息，不应手动强制提交。

## 常见问题

### 为什么首次打开没有项目？

应用不会把开发夹具伪装成真实项目。请选择“添加项目”录入自己的内容。

### 为什么换了端口或浏览器后项目仍然存在？

当前版本以项目根目录的 `data/` 为主存储，不再按浏览器来源隔离。只要从同一个项目目录启动，应用就会读取同一组分类文件。

### 为什么本地路径不能直接打开？

普通网页不能随意打开本机文件。路径字段只作为文本保存，详情页提供复制操作；需要读取状态时，请主动使用文件或目录选择器授权。

### “可能停滞”表示项目出现问题了吗？

不是。它只是工作台根据“未完成且至少 14 天未更新”计算的提醒，不会修改项目状态。

### 删除集合或模板会删除项目吗？

不会。删除集合只解除项目关联，删除模板也不影响已有项目和笔记。

### 删除项目会发生什么？

删除项目会把它及其关联研究笔记、草稿、正式版本历史和自动事件一起移入回收站，保留 7 天；在此期间可在“设置 → 回收站”中恢复。回收站最多保留 30 条条目，超过上限或到期后会自动清理。

### Markdown 内容会上传吗？

不会。指南、研究笔记预览和 Codex 上下文都在浏览器本地处理，不调用远程渲染服务。

### 数据损坏或误删后怎么办？

先关闭本地服务并备份整个 `data/`。如果有应用 JSON 备份，可重新启动后使用“替换导入”恢复；损坏文件不会被应用自动覆盖，也不会从云端恢复。
